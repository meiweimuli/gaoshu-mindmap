  • 计算机网络
    • 体系结构
      • 概念
        • 计算机网络
          • 由若干结点和连接这些结点的链路组成
        • 互连网
          • 多个计算机网络通过路由器连接成的计算机网络
          • 互连网可使用任意通信协议
        • 互联网
          • 全世界最大的特定计算机网络
          • 使用 TCP/IP 协议
        • ISP 与网络设备
          • ISP（因特网服务提供者）
            • 是向用户提供因特网接入及相关服务的机构
              • 用户需先接入某个 ISP 才能连入因特网
          • 网络互连设备
            • 集线器用于同一网络内部的连接
            • 交换机用于同一网络内部的连接
            • 路由器用于连接不同的网络
          • 家用路由器
            • 兼具路由、交换与无线接入功能
              • 供家庭中多台设备共享上网
      • 组成
        • 按组成部分
          • 硬件、软件、协议
        • 按工作方式
          • 边缘部分、核心部分
        • 按逻辑功能
          • 资源子网、通信子网
      • 功能
        • 数据通信
          • 最基本、最重要的功能
        • 资源共享
          • 包括硬件、软件、数据资源的共享
        • 分布式处理
          • 多台计算机分工协作完成同一任务
        • 提高可靠性
          • 网络中的计算机可互为备份
        • 负载均衡
          • 将任务均衡分配给多台计算机处理
      • 交换技术
        • 电路交换
          • 优点
            • 通信时延小（建立连接后数据直达，无存储转发时延）
            • 传输有序，不存在失序问题
            • 无冲突，实时性强，适用于实时通信
            • 控制简单，便于硬件实现
          • 缺点
            • ①建立连接，额外开销
            • ②独占线路，利用率低
            • ③线路分配灵活性差
            • ④不支持差错控制
        • 报文交换
          • 优点
            • ①无需建立连接
            • ②无需独占，利用率高
            • ③存储转发，分配灵活
            • ④支持差错控制
          • 缺点
            • ①转发时延高
            • ②报文大小无限制，缓存开销大
            • ③长报文容易出错，重传代价大
        • 分组交换
          • 优点
            • ①分组大小有限制，缓存开销小
            • ②分组逐个传输，传输效率高
            • ③分组短，不易出错，重传代价小
          • 缺点
            • ①（相比电路交换）存储转发延时
            • ②（相比报文交换）控制信息增加
            • ③分组多，有失序丢失问题，增加处理复杂度
        • 交换方式性能对比
          • 完成传输所需时间：电路交换 最少（排除建立/释放连接耗时）；报文交换 最多；分组交换 较少
          • 存储转发时延：电路交换 无；报文交换 较高；分组交换 较低
          • 通信前是否需要建立连接：电路交换 是；报文交换 否；分组交换 否
          • 缓存开销：电路交换 无；报文交换 高；分组交换 低
          • 是否支持差错控制：电路交换 不支持；报文交换 支持；分组交换 支持
          • 报文数据有序到达：电路交换 是；报文交换 是；分组交换 否
          • 是否需要额外的控制信息：电路交换 否；报文交换 是；分组交换 是（控制信息占比最大）
          • 线路分配灵活性：电路交换 不灵活；报文交换 灵活；分组交换 非常灵活
          • 线路利用率：电路交换 低；报文交换 高；分组交换 非常高
          • 三种交换方式的传送过程
            • 电路交换：连接建立 → 数据传送 → 连接释放
            • 电路交换数据传送的特点：比特流直达终点
            • 报文交换：整个报文采用存储转发
            • 报文交换数据传送的特点：报文 存储转发
            • 分组交换：报文划分为分组，采用存储转发
            • 分组交换数据传送的特点：分组 存储转发

          • 总线结构、环状结构、星形结构、网状结构

          • 有线网、无线网
      • 性能指标
        • 速率
          • 又称比特率，指单位时间内传送的比特数
          • 单位 bps（bit/s，比特每秒）
            • 数量级前缀 K、M、G、T
              • 网络与通信领域按 $10$ 的幂计，如 $10^3$、$10^6$
              • 存储器等其他领域按 $2$ 的幂计，如 $2^{10}$、$2^{20}$
        • 带宽
          • 信道所能传送的最高速率
        • 吞吐量
          • 单位时间实际数据量
        • 时延
          • 发送时延（传输时延）$=$ 数据大小 $/$ 发送速率
          • 传播时延 $=$ 信道长度 $/$ 电磁波传播速率
          • 处理时延、排队时延
            • 处理时延：主机或路由器处理分组（分析首部、提取数据、差错检验、查找转发表等）所花费的时间
            • 排队时延：分组在结点缓存队列中等待转发所经历的时间，随网络负载动态变化
          • 总时延 $=$ 各结点发送时延之和 $+$ 各链路传播时延之和 $+$ 处理时延 $+$ 排队时延
        • 时延带宽积
          • 时延带宽积 $=$ 传播时延 $\times$ 带宽
          • 已发送但未到达的最大比特数
        • 往返时延
          • 往返时间
            • 发送方 A 向接收方 B 发送数据，接收方 B 回送确认
            • 发送时延 $t_1$ 指发送数据所需的时间
            • 数据传播时延 $t_2$
            • 处理时延 $t_3$
            • 确认发送时延 $t_4$
            • 确认传播时延 $t_5$
            • 往返时间 $RTT=t_1+t_2+t_3+t_4+t_5$
          • 从发送方开始发送数据，到收到接收方确认所经历的时间
        • 信道利用率
          • 信道利用率 $=$ 有数据通过的时间 $/$ 总时间
          • 利用率过低浪费资源，过高易造成网络拥塞
      • 分层结构
        • 实体、协议、接口与服务
          • 第 $n+1$ 层、第 $n$ 层
            • 第 $n+1$ 层是第 $n$ 层的服务用户，第 $n$ 层是第 $n+1$ 层的服务提供者
            • 相邻层之间通过对等服务访问点（SAP）交换服务原语
          • 服务用户（上层实体）使用下层提供的服务
          • 服务提供者（下层实体）为上层提供服务
          • 不同系统中同一层的实体（如两个第 $n$ 层实体）互为对等实体
          • 协议 $(n+1)$、协议 $(n)$ 为同层对等实体间的水平方向规则
          • 交换服务原语在相邻层之间沿垂直方向传递
          • SAP 为服务访问点
        • PDU、PCI、SDU
          • $n\text{-SDU}+n\text{-PCI}=n\text{-PDU}=(n-1)\text{-SDU}$
          • PDU 为本层协议数据单元，由本层 SDU 与本层 PCI 组成
          • PCI 为本层控制信息
          • SDU 为上层交下来的数据
        • 协议三要素
          • 语法规定数据与控制信息的格式
          • 语义规定数据的含义以及应执行的动作
          • 时序规定通信的先后顺序、同步与速率
        • 服务分类
          • 面向连接服务与无连接服务
            • 面向连接服务：通信前先建立连接，数据按序传送，结束后释放连接（如电话、TCP）
            • 无连接服务：无需建立连接，各分组独立传送，路径与到达顺序不固定（如邮政、UDP/IP）
          • 可靠服务和不可靠服务
            • 可靠服务：保证数据无差错、不丢失、不重复且按序到达，通常依靠确认与重传实现
            • 不可靠服务：不保证上述性质，可靠性由用户或上层协议承担
          • 有应答服务和无应答服务
            • 有应答服务：接收方收到数据后向发送方返回应答（确认）
            • 无应答服务：接收方不返回应答，发送方无法确知数据是否被接收
        • 网络体系结构模型
          • OSI参考模型
            • 物理层
              • 相邻节点比特传输
              • 电路接口参数
              • 传输信号含义，电气特征
            • 数据链路层
              • 相邻节点链路逻辑无差错
              • 差错控制
                • 检测并纠正相邻结点间链路上传输产生的比特差错，使物理链路对上层表现为无差错
                • 常用方法有检错重发（ARQ）和前向纠错（FEC）
              • 流量控制
                • 协调相邻结点收发双方的速率，使发送方发送速率不超过接收方的接收与处理能力
                • 常借助滑动窗口机制实现
            • 网络层
              • 分组从源结点转发到目的结点
                • 路由选择
                  • 分组转发
                    • 路由器根据转发表，将到达的分组从相应的输出端口转发出去
                  • 为分组从源结点到目的结点选择一条合适的传输路径
                  • 依据路由协议与路由算法建立并维护路由表
                • 拥塞控制
                  • 当网络负载超过其处理能力时，限制注入网络的通信量，避免吞吐量下降、时延急剧增大
                  • 目标是使网络保持高吞吐、低时延的运行状态
                • 网际互联
                  • 通过路由器把多个异构网络互连，屏蔽底层网络差异，构成统一的逻辑网络
                • 其他功能：差错控制，流量控制，连接建立和释放，可靠传输管理
            • 传输层
              • 端到端通信
                • 复用和分用
                  • 复用：发送方多个应用进程的数据共用同一个传输层实体传送
                  • 分用：接收方传输层根据端口号把数据交付给正确的应用进程
                • 其他功能：差错控制，流量控制，连接的建立与释放，可靠传输管理
                • 提供两台主机中应用进程之间的逻辑通信（进程到进程），而非主机到主机或结点到结点
                • 通信过程对上层透明，仿佛两端进程直接相连
            • 会话层
              • 管理进程间会话
              • 会话管理
            • 表示层
              • 处理信息表示不一致
              • 数据格式转换
                • 把不同主机采用的字符编码、数据表示格式（如 ASCII 与 EBCDIC）统一转换为标准形式
                • 同时处理数据的压缩与加密
            • 应用层
              • 直接为应用进程提供网络服务
                • 是用户与网络的接口
              • 典型协议有 HTTP、FTP、SMTP 和 DNS
          • TCP/IP模型
            • 网络接口层
              • 相邻节点数据传输，不做详细规定
            • 网络层
              • 尽力交付
                • 路由选择
                  • 分组转发
                    • 路由器根据转发表，将到达的分组从相应的输出端口转发出去
                  • 为分组从源结点到目的结点选择一条合适的传输路径
                  • 依据路由协议与路由算法建立并维护路由表
                • 拥塞控制
                  • 当网络负载超过其处理能力时，限制注入网络的通信量，避免吞吐量下降、时延急剧增大
                  • 目标是使网络保持高吞吐、低时延的运行状态
                • 网际互联
                  • 通过路由器把多个异构网络互连，屏蔽底层网络差异，构成统一的逻辑网络
                • 网络层只尽最大努力转发分组，不保证分组可靠、不丢失、不重复、不失序，也不保证时延
                • 对上层不提供质量承诺，可靠性由传输层负责保证
            • 传输层
              • 提供进程间端到端逻辑通信（TCP 可靠、UDP 不可靠）
                • 复用和分用
                  • 复用：发送方多个应用进程的数据共用同一个传输层实体传送
                  • 分用：接收方传输层根据端口号把数据交付给正确的应用进程
                • 差错控制
                  • 检测并处理端到端传输中出现的差错（出错、丢失、重复、失序），保证数据正确交付
                  • 常通过序号、确认与重传机制实现
                • 流量控制
                  • 协调收发两端应用进程的发送与接收速率，防止接收方缓冲区溢出
                  • 由接收方通过窗口通告控制发送方的发送量
                • 连接建立和释放
                  • 面向连接的传输协议在传送数据前先建立连接，传送结束后释放连接
                  • 如 TCP 用三次握手建立连接、四次挥手释放连接
                • 可靠传输管理
                  • 通过序号、确认、重传、窗口等机制，使数据无差错、不丢失、不重复且按序到达
            • 应用层
              • 数据表示与会话管理由各应用自己的协议完成
          • OSI 与 TCP/IP 模型的区别
            • OSI 网络层支持面向连接与无连接，传输层只支持面向连接；TCP/IP 网络层只支持无连接，传输层两种都支持
            • OSI 分为 7 层，TCP/IP 只有 4 层
            • OSI 是法定标准，TCP/IP 是事实标准
    • 物理层
      • 概念
        • 数据通信系统的组成
          • 信源：产生并发送数据
          • 信道：传输信号的通道（单向）
          • 信宿：接收数据
        • 数据
          • 运送信息的实体
        • 信号
          • 数据的电气或电磁表现形式
        • 码元
          • 用固定时长的信号波形表示一位 $k$ 进制数，1 码元可携带 $\log_2 k$ bit
        • 码元传输速率
          • 又称波特率、调制速率，每秒传输的码元数，单位波特（Baud）
        • 信息传输速率
          • 又称比特率，每秒传输的比特数，单位 b/s
        • 带宽
          • 信号所占据的频率范围，为最高频率与最低频率之差，单位 Hz
      • 信道极限容量
        • 奈奎斯特定理（无噪声）
          • 极限波特率
            • 理想低通信道极限波特率 $=2W$ Baud；理想带通信道为 $W$ Baud
          • 极限比特率
            • $C=2W\log_2 K$ b/s（$K$ 为一个码元所取的离散电平数）
          • 奈氏准则只限制码元传输速率，不限制信息传输速率
        • 香农定理（有噪声）
          • 极限比特率
            • $C=W\log_2(1+S/N)$ b/s，带宽受限、有高斯白噪声信道的理论上限
          • 信噪比
            • 无单位形式：$S/N$
            • 分贝形式：$10\lg(S/N)$ dB
      • 编码和调制
        • 编码
          • 把数据转换为数字信号
        • 解码
          • 把数字信号还原为数据
        • 调制
          • 把数据转换为模拟信号
        • 解调
          • 把模拟信号还原为数据
        • 常见编码
          • 非归零编码NRZ
            • 高1低0中不变
          • 归零编码RZ
            • 高1低0中归零
          • 反向非归零编码NRZI
            • 起变0不变1中不变
          • 曼彻斯特编码
            • 中上0下1
          • 差分曼彻斯特编码
            • 起变0不变1中变
          • 常见编码波形示例
            • 二进制数据：$1\ 1\ 1\ 1\ 0\ 0\ 1\ 0$
            • 非归零编码：高电平表示 1，低电平表示 0，码元内电平不归零
            • 归零编码：每个码元中间电平归零
            • 反向非归零编码：电平不变表示 1，电平跳变表示 0
            • 曼彻斯特编码：每个码元中间发生电平跳变
            • 差分曼彻斯特编码：码元开始处有跳变表示 0，无跳变表示 1
          • 常见编码性能对比
            • 自同步能力：不归零（NRZ）无；归零（RZ）有；反向非归零（NRZI）若增加冗余位可实现自同步；曼彻斯特 有；差分曼彻斯特 有
            • 浪费带宽：不归零（NRZ）无；归零（RZ）浪费；反向非归零（NRZI）不太浪费；曼彻斯特 浪费；差分曼彻斯特 浪费
            • 抗干扰能力：不归零（NRZ）弱；归零（RZ）弱；反向非归零（NRZI）弱；曼彻斯特 强；差分曼彻斯特 强
          • 编码的区分方法
            • 中变：曼彻斯特（中变一一对应）、差分曼彻斯特
            • 中不变：NRZ（高低一一对应）、NRZI
            • 中归零：RZ
        • 常见调制
          • 调幅AM（ASK）
            • 用载波幅度的变化表示数字信息
          • 调频FM（FSK）
            • 用载波频率的变化表示数字信息
          • 调相PM（PSK）
            • 用载波相位的变化表示数字信息
          • 正交幅度调制QAM
            • 同时利用幅度与相位调制
              • 每码元有 $m$ 种幅值、$n$ 种相位
              • 记作 QAM-$mn$
              • 1 码元 $=\log_2(mn)$ bit
          • 常见调制方式对比
            • 基带信号序列：$0\ 1\ 0\ 0\ 1\ 1\ 1\ 0$
            • 调幅（AM）：基带为$1$时输出有幅度载波，为$0$时无幅度
            • 调频（FM）：基带为$1$时载波频率为$f_1$，为$0$时频率为$f_2$，相位连续
            • 调相（PM）：基带为$1$时相位为$\pi$，为$0$时相位为$0$
      • 传输介质
        • 传输介质的分类
          • 导向型
            • 双绞线
              • 由两根相互绝缘的导线绞合而成
              • 分类
                • 有屏蔽层STP
                  • STP 指屏蔽双绞线（Shielded Twisted Pair）
                  • 在双绞线外增加金属屏蔽层，可减小电磁干扰和串扰
                  • 抗干扰能力强、保密性好，但价格较贵、体积较大、安装较麻烦
                • 无屏蔽层UTP
                  • UTP 指非屏蔽双绞线（Unshielded Twisted Pair）
                  • 仅由相互绝缘的导线绞合而成，无金属屏蔽层
                  • 价格便宜、使用方便，是最常用的双绞线（如 5e、6 类双绞线）
            • 同轴电缆
              • 由内导体和外导体屏蔽层构成
            • 光纤
              • 由高折射率纤芯和低折射率包层构成
              • 光纤的分类
                • 多模光纤
                  • 纤芯粗，同时多条光线，损耗高
                  • 适合近距离
                • 单模光纤
                  • 纤芯细，一条光线，损耗低
                  • 适合远距离
            • 以太网物理层命名规则
              • 速度+Base+介质信息
                • 10Base5、10Base2、10BaseT*、10BaseF*
                  • 10Base5：速率 10 Mb/s、基带传输、粗同轴电缆，网段最大长度 500 m
                  • 10Base2：速率 10 Mb/s、基带传输、细同轴电缆，网段最大长度约 185 m
                  • 10BaseT：速率 10 Mb/s、基带传输、双绞线（T 表示 Twisted Pair）
                  • 10BaseF：速率 10 Mb/s、基带传输、光纤（F 表示 Fiber）
            • 三种导向型介质的对比
              • 抗干扰能力：双绞线 < 同轴电缆 < 光纤
              • 传输损耗：双绞线 > 同轴电缆 > 光纤
          • 非导向型
            • 无线电波
              • 穿透能力强、传输距离长、指向型弱
              • 典型应用：手机信号、WiFi
            • 微波通信
              • 频率带宽高、指向型强、保密性差
              • 卫星通信也属于微波通信
            • 其他非导向介质
              • 典型例子：红外线、激光
            • 电磁波传播的一般规律
              • 波长越长，绕射性越好
              • 长波适合长距离非直线通信；微波适合短距离高速通信，长距离（视距）通信中继站需强指向性、用微波
              • 频率越高，数据传输能力越强、指向性越强
      • 物理层设备
        • 中继器
          • 两个端口，一端接收、一端发送
          • 信号整形再生的过程
            • 上：发送端原始数字信号（规整方波，取值$0/1$）
            • 中：经信道长距离传输后幅度衰减、波形失真的接收信号
            • 下：经中继器整形再生后恢复的规整数字信号
          • 半双工，两端不能同时发送数据
          • 对应两个网段
        • 集线器
          • 多端口中继器，一端接收，其余端口整形再生
          • 同一时刻只能有一个端口发送，否则冲突
          • n 个端口对应 n 个网段，同属于一个冲突域
        • 集线器与中继器的特性
          • 不能无限串联
          • 集线器连接的网络，物理星型，逻辑总线
          • 集线器各网段共享带宽
          • 集线器可以链接不同传输介质
          • 集线器各网段速率向下兼容

          • 电气特性：规定接口电缆上各条线的电压范围
          • 功能特性：规定某条线上某一电平的电压表示何种意义
          • 过程特性：规定各类功能可能出现的时序关系
    • 数据链路层
      • 数据链路层的主要功能
        • 为网络层提供服务：无确认无连接、有确认无连接、有确认面向连接三类服务
        • 组帧：把网络层的数据单元封装成帧，实现帧定界与透明传输
        • 差错控制：检测并处理帧在传输中产生的比特差错
        • 流量控制：控制相邻结点之间的发送速率，使接收方来得及处理
        • 链路管理：数据链路的建立、维持和释放
      • 组帧
        • 组帧的目标
          • 帧定界
            • 让接收方确定帧的边界
          • 透明传输
            • 让接收方能把帧恢复原貌
        • 组帧的方法
          • 字符计数法
            • 帧开头添加计数字段
            • 帧长包括计数字段
          • 字节填充法
            • 特殊字符
              • 控制字符SOH、EOT
                • SOH（Start Of Heading）：放在帧首，标志一帧的开始
                • EOT（End Of Transmission）：放在帧尾，标志一帧的结束
              • 转义字符ESC
                • ESC（Escape）：当数据部分出现 SOH、EOT、ESC 等特殊字符时，在其前面插入转义字符，避免与控制字符混淆
            • 发送方在帧数据部分的特殊字符前加转义字符
            • 接收方遇到转义字符直接把后续字符作为数据
          • 零比特填充法
            • 以$01111110$作为帧的开始与结束标志
            • 发送方在帧内部每遇到连续5个1，就在其后插入一个0
            • 接收方在帧内部每遇到连续5个1，就删除其后的0
            • HDLC协议、PPP协议
              • HDLC 协议、PPP 协议都采用零比特填充法实现透明传输
          • 违规编码法
            • 用违反编码规则的信号作为帧的起止标志，需要物理层配合
            • 例如曼彻斯特编码中位中间不跳变（高-高/低-低）作为帧的起止标志
      • 差错控制
        • 差错控制的目的
          • 发现帧内部的位错
        • 差错控制的解决方法
          • 检错
            • 发现后丢弃帧，并通知重传
          • 纠错
            • 发现并纠正比特错误
        • 奇偶校验
          • 在信息位前或后增加一位校验位
          • 奇校验
            • 整个校验码1的个数为奇数
          • 偶校验
            • 整个校验码1的个数为偶数
          • 仅能检测出奇数位错误
          • 偶校验异或运算，为1说明出错
        • 循环冗余校验CRC
          • CRC的基本思想
            • 收发双方约定一个除数，发送方保证数据位添加校验位后除法余数为0
          • CRC校验码的构造
            • 生成多项式$G(x)$的最高次为$R$，对应的除数共$R+1$位
            • $K$个信息位后补$R$个0作为被除数
            • 模2除，得$R$位余数
              • 异或代替减法，余数首位就是商的这一位，其余和除法一样
            • $K$个信息位$+$$R$位余数$=$CRC校验码
          • CRC的校验
            • 收到$K+R$位数据，与除数模2除，得$R$位余数
            • 余数不等于0，说明出错
          • CRC的检错纠错能力
            • 可检测出奇数个比特错误
            • 可检测出双比特错误
            • 可检测出长度不超过$R$的连续错误（突发错误）
            • 信息位较短时可纠正单比特错误：$2^R\ge K+R+1$
        • 海明码
          • 分组偶校验
            • 海明码把信息位分成若干组，分别进行偶校验
            • 由各组校验结果综合定位并纠正一位错误
          • 海明码的编码步骤
            • 确定校验位个数
              • $2^k\ge n+k+1$（$k$为校验位个数，$n$为信息位个数）
            • 确定校验位位置：$p_i$放在第$2^{i-1}$位
            • 分组求校验位
              • 位置序号用$k$位二进制表示
              • $p_i$与位置序号第$i$位为1的信息位分为一组，求偶校验
          • 海明码的纠错
            • 各校验组分别异或得到$S_i$
            • 各校验组结果全为0表示无错误
            • 由$S_3S_2S_1$的取值确定出错位置
        • 码距
          • 编码集合中任意两个码字异或后1的个数的最小值
          • 检测$n$位错要求最小码距$d_{\min}\ge n+1$
          • 纠正$n$位错要求最小码距$d_{\min}\ge 2n+1$
      • 流量控制和可靠传输
        • 流量控制与可靠传输的概念
          • 滑动窗口机制
            • 发送窗口WT
              • 发送窗口内的帧允许被发送
            • 接收窗口WR
              • 接收窗口内的帧允许被接收
            • 接收方通过确认机制控制发送窗口前滑，实现流量控制
          • 流量控制
            • 接收方控制发送方的发送速率
              • 一般用滑动窗口机制实现
            • 数据链路层和传输层都有流量控制功能
              • ①数据链路层控制相邻节点流量，传输层控制端到端流量
              • ②数据链路层窗口不变，传输层通过确认报文调整发送窗口
          • 可靠传输
            • 发送方发送的数据都能被接收方正确接收
              • 一般通过确认和超时重传实现，实现这两种机制的协议称为自动重传请求ARQ，包括SW、GBN、SR
        • 停止等待协议SW
          • 滑动窗口
            • $W_T=1$，$W_R=1$
          • 确认机制
            • 确认帧ACK_i
              • 接收方正确收到第 $i$ 号帧后，返回确认帧 ACK$_i$
          • 重传机制
            • 超时重传
              • 数据帧丢失或出错
              • 确认帧丢失
          • 帧编号
            • 帧序号1位（0/1）
          • 流量控制
            • 发送确认帧后接收窗口向右滑动
            • 收到确认帧后发送窗口向右滑动
          • 可靠传输
            • 收到窗口外数据帧直接丢失，返回该帧的确认帧
            • 检测出差错直接丢弃
            • WR=1，只能顺序接收帧，不存在数据帧失序
        • 后退n帧协议 GBN
          • 滑动窗口
            • $W_T>1$，$W_R=1$
          • 确认机制
            • 确认帧ACK_i
              • 可以累积确认，连续收到多个帧，可以仅返回最后一个帧的ACK
          • 重传机制
            • 超时重传
              • 超时未收到ACK_i，则重传i号帧及其后的所有帧
          • 帧编号
            • $W_T+W_R\le 2^n$
          • GBN的特殊规则
            • ①累积确认
            • ②超时未收到ACK_i则重传i号帧及其后的所有帧
          • GBN的其他要点
            • 收到窗口外数据帧或差错帧直接丢失，并返回目前已接收的最后一个正确帧的ACK_i
            • 缺点，如果接收方慢，或差错多，可能会经常回退，效率低
        • 选择重传协议SR
          • 滑动窗口
            • $W_T>1$，$W_R>1$，$W_T\ge W_R$，通常$W_T=W_R$
          • 确认机制
            • 确认帧ACK_i
              • 收到没有差错的i号帧，需要返回确认帧ACK_i
            • 否认帧NAK_i
              • 若接收方收到的i号帧有差错，丢弃该帧，并发送否认帧NAK_i
          • 重传机制
            • 超时重传
              • 发送方为每个已发送未确认的帧分别设置计时器
              • 某帧计时器超时仍未收到确认，则只重传该帧
            • 请求重传
              • 接收到NAK_i，则重传i号帧
          • 帧编号
            • $W_T+W_R\le 2^n$
          • SR的特殊规则
            • ①否认帧
            • ②请求重传
            • ③$W_T\ge W_R$
          • SR的其他要点
            • 接收方不能累计确认，要一帧一确认
            • 可能会帧失序，需要接收窗口大小的缓冲
        • 信道利用率
          • 停止等待协议
            • 总耗时$=$单帧发送时间$+$两倍单向传播延迟$+$确认帧发送时间
            • 有效发送时间$=$单帧发送时间
          • 后退n帧协议、选择重传协议
            • 总耗时$=$单帧发送时间$+$两倍单向传播延迟$+$确认帧发送时间
            • 有效发送时间$=$发送窗口内$W_T$帧总发送时间
            • 信道利用率$=$有效发送时间$\div$总耗时$\le 1$
        • 其他相关术语
          • 滑动窗口协议
            • 发送方在发送窗口内的帧可连续发送，不必逐帧等待确认
            • 接收方通过确认使发送窗口向前滑动，从而实现流量控制
          • ARQ协议与连续ARQ协议
            • ARQ（自动重传请求）：通过确认与超时重传实现可靠传输
            • 停止等待协议是发送窗口为1的ARQ
            • 连续ARQ一次可连续发送多帧，包括后退N帧协议GBN和选择重传协议SR
      • 介质访问控制
        • 介质访问控制的概念
          • 多节点共享广播信道，控制可能发生的信号冲突
        • 信道划分
          • 时分复用TDM
            • 均分时间片
          • 统计时分复用STDM
            • 按需分配时间片
          • 频分复用FDM
            • 总频带拆分成多个子频带
          • 波分复用WDM
            • 光的频分复用
          • 码分复用CDM
            • 给各结点分配码片序列
              • 码片序列包含m个1和-1
              • 各结点码片序列相互正交
              • 各结点码片序列相互知道
            • 发送数据
              • 码片序列表示1
              • 码片序列相反表示0
            • 各结点数据加法叠加
            • 接收数据
              • 叠加信号与发送方码片序列规格化内积
                • 结果为1表示1
                • 结果为-1表示0
        • 随机访问
          • ALOHA协议
            • 纯ALOHA协议
              • 准备好数据立即发送，等待随机时间没收到ACK时重发
            • 时隙ALOHA协议
              • 划分时隙，准备好数据后在首个时隙开头发送，等待随机时间没收到ACK再在首个时隙开头重送
              • 避免了随意性，降低了冲突概率，提高了信道利用率
          • CSMA协议
            • 监听信道是否空闲，空闲时发送
            • 1-坚持CSMA协议
              • 持续监听信道，信道一空闲就发送数据
              • 优点，信道利用率高
              • 缺点，多结点同时监听，空闲时会同时发送产生冲突
            • 非坚持CSMA协议
              • 随机间隔监听信道
              • 优点，随机推迟监听可以错开发送数据，降低冲突概率
              • 缺点，恢复空闲后不能立即利用，利用率降低
            • p-坚持CSMA协议
              • 持续监听，空闲时有p概率立即发送，1-p概率等待一段时间再继续监听
            • 三种CSMA协议比较
              • 表3.1 三种不同类型的CSMA协议比较
              • 信道空闲·1-坚持：立即发送数据
              • 信道空闲·非坚持：立即发送数据
              • 信道空闲·p-坚持：以概率$p$发送数据，以概率$1-p$推迟到下一个时隙
              • 信道忙·1-坚持：继续坚持监听
              • 信道忙·非坚持：放弃监听，等待一个随机的时间后再监听
              • 信道忙·p-坚持：持续监听（等到下一时隙再监听），直至信道空闲
          • CSMA/CD协议
            • 先听后发，边听边发，冲突停发，随机重发
            • 随机重发
              • 截断二进制指数退避算法
                • 随机等待时间$=r\times$争用期
                • 冲突次数$k$，在$[0,2^{\min(k,10)}-1]$中随机取$r$
                • 冲突次数$k=16$，直接放弃
            • 争用期（冲突窗口）
              • 争用期的长度
                • 超过争用期没有冲突后就不会再冲突
                • CSMA/CD没有ACK机制，发送过程中没有冲突就认为发送成功
              • 两端冲突检测示例
                • A、B两站相距$1\,\mathrm{km}$，单程端到端传播时延记为$\tau$
                • $t=0$：A开始发送数据
                • $t=\tau-\delta$：B检测到信道空闲，开始发送数据
                • $t=\tau-\delta/2$：A、B发送的数据发生冲突
                • $t=\tau$：B检测到发生冲突，停止发送
                • $t=2\tau-\delta$：A检测到发生冲突
                • 争用期（冲突窗口）为$2\tau$
            • 最短帧长
              • 最短帧长$=2\tau\times$信道带宽
                • 收到小于最短帧长的帧视为无效帧
            • 最长帧长
              • 避免结点长期占用信道
            • 以太网的最短与最长帧长
              • 最短帧长64B，最长帧长1518B
            • CSMA/CD发送流程
              • 等待下一帧准备好
              • 监听信道（发送前）
              • 信道空闲？不空闲则继续监听
              • 空闲则立即把帧发送到信道上
              • 边发送边监听
              • 发送过程中检测到冲突？无冲突则传输成功
              • 有冲突则立即停发，判断这是第$k$次冲突
              • $k\le 15$：随机等待一段时间后重新监听信道
              • $k=16$：传输失败，放弃传输此帧，并报告网络层
              • 争用期$=2\times$最远单向传播时延（考虑距离最远的两个节点）
              • 若争用期内没检测到冲突，本次帧发送就不再可能发生冲突
              • 截断二进制指数退避算法：随机等待时间$=r$倍争用期，$r$为随机数
              • ①若$k\le 10$，在$[0,2^k-1]$区间随机取一个整数$r$
              • ②若$k>10$，在$[0,2^{10}-1]$区间随机取一个整数$r$
          • CSMA/CA协议
            • 小帧发送流程（直接发送数据帧）
              • 信道忙或准备好数据→持续DIFS空闲→持续backoff空闲→数据帧→SIFS→ACK帧
                • CSMA/CA小帧时序
                  • 横轴为时间，涉及STA1与STA2两个站点
                  • STA1先等待DIFS，随后信道忙（Busy medium，被其他站点占用），之后再次等待DIFS
                  • STA2等待DIFS后发送数据帧PACKET A（To AP方向）
                  • 数据帧结束后等待SIFS（短帧间间隔），AP返回ACK帧（From AP方向）
                  • ACK后STA2再次等待DIFS
                  • 时隙Slot Time用于退避计数（图中标注时隙编号$8\ 7\ 6\ 5$、$2\ 1\ 0$）
                  • 帧间间隔关系：DIFS > SIFS
            • 大帧发送流程（RTS/CTS）
              • 信道忙或准备好数据→持续DIFS空闲→持续backoff空闲→RTS帧→SIFS→CTS帧→SIFS→数据帧→SIFS→ACK帧
                • CSMA/CA 大帧 RTS/CTS 传输时序
                  • STA1、STA2 先持续监听 DIFS 空闲，再各自进入退避计数
                  • STA1 退避计数 6→3，STA2 退避计数 3→0，STA2 先退避到 0 抢先发送
                  • STA2 先发送 RTS 帧，其余站点据此设置 NAV 并保持静默
                  • 各帧之间间隔均为 SIFS，STA2 收到 CTS 帧后发送数据帧 PACKET A
                  • STA2 收到 ACK 帧后完成一次传输，随后再次监听 DIFS 并进行退避
                  • 大帧帧交换顺序：DIFS → 退避 → RTS → SIFS → CTS → SIFS → 数据帧 → SIFS → ACK
                  • NAV 覆盖从 RTS/CTS 交换到 ACK 结束的整个时段，期间其他站点推迟访问
            • 如果在预计时间内没有收到ACK帧，则发送流程重新开始，退避指数加一
            • 等待 DIFS 期间信道变忙→重新等待 DIFS；退避计时期间信道变忙→冻结退避计时器、保留剩余值，空闲后继续倒计时
              • 如果是不是给自己帧，且duration>NAV，则更新NAV值为duration，NAV是时间倒计时器
              • 如果收到的是ACK帧，则清空NAV值
            • duration表示收到此帧后本次传送剩余时间
              • RTS帧的duration=SIFS+CTS+SIFS+PACKET+SIFS+ACK
              • CTS帧的duration=SIFS+PACKET+SIFS+ACK
            • 信道忙包括 物理载波监听和虚拟载波监听（NAV>0）
            • 退避：若上次退避未完成则沿用剩余值，否则在$[0,CW]$中随机取值，$CW=2^{2+k}-1$（$k$为未收到ACK的次数，最大为6）
        • 轮询访问
          • 令牌传递协议
            • 令牌传递协议的要点
              • 令牌帧
                • 包含获得令牌的结点编号
                • 获得令牌帧的结点能发送数据帧
                • 没有数据发送或发送完成一帧，就将令牌传给下一结点
              • 数据帧
                • 包含获得令牌的结点编号，源目的地址，是否已被接收
                • 数据帧从源结点发出，传递一圈返回源结点，传递经过目的结点时复制一份数据，并标记已接收
                • 传递一圈后如有异常就重发，否则将令牌传递给下一结点
            • 令牌传递协议的补充说明
              • 单向传递
                • 令牌只沿环的一个方向依次传递，不双向传输
              • 需要专门网络设备MAU集中控制
              • 适合负载高的网络，不会发送冲突

        • IEEE802.3以太网
          • 以太网的物理层标准
            • 传输介质与物理层标准命名
              • 同轴电缆 10Base5、10Base2
                • 10Base5：10 Mb/s 基带传输、粗同轴电缆，网段最大长度 500 m

                • 10BaseT：10 Mb/s 基带传输、双绞线（T 表示 Twisted Pair）

                • 10BaseF：10 Mb/s 基带传输、光纤（F 表示 Fiber）

            • 半双工模式下需要CSMA/CD协议实现介质访问控制

                • 仅半双工
              • 双绞线
                • 连接集线器只能半双工
                • 连接交换机默认全双工
              • 光纤
                • 仅全双工

            • 以太网MAC帧格式
              • V2标准
                • 662n4 收发协数验，n：46-1500
              • 802.3标准
                • 662n4 收发长数验
            • MAC地址6B，48bit，目的地址全1表示广播帧
              • 交换机会将广播帧转发
              • 路由器不会转发广播帧

            • 解决大型局域网可能出现的广播风暴和信息安全问题

          • VLAN的划分方式
            • 基于接口
              • 交换机内部数据结构记录VID和交换机接口映射关系
            • 基于MAC地址

          • 802.1Q帧
            • 主机与交换机使用标准以太网帧

            • VLAN标签 16bit+4bit+12bit 固定+随意+VID
        • 802.11无线局域网
          • 802.11的基本概念
            • 接入点AP（无线接入点）
              • AP是把无线站点接入有线网络的设备，工作在数据链路层
              • AP负责无线链路与有线链路之间帧的转发及802.11与802.3帧格式的转换
            • 基本服务集BSS
              • 服务集标志SSID
                • SSID是无线网络的名称标识，最长32字节
                • 同一ESS内各AP使用相同的SSID
              • 基本服务区BSA
                • BSS覆盖地理范围
            • 扩展服务集ESS
              • 由多个BSS通过分布式系统（通常是以太网）连接而成
              • ESS用于扩大无线覆盖范围，支持站点漫游
            • 漫游
              • 移动站从一个BSS移动到另一个BSS时通信不中断
              • 同一ESS内各AP使用相同的SSID，漫游由各AP协同完成
            • 门户Portal
              • Portal是802.11中用于接入认证的站点，如提供登录或付费页面
              • Portal位于无线局域网与有线网络之间，常与认证服务器配合
          • 802.11帧
            • 802.11帧的分类
              • 数据帧
                • 802.11数据帧用于承载上层数据，帧头中最多含4个地址字段
                • 地址字段用于区分源、目的、AP及路由器等，帧的中转靠AP完成
              • 控制帧
                • ACK、RTS、CTS
                  • ACK：确认帧，接收方正确收到数据帧后回复
                  • RTS：请求发送帧（Request To Send），发送方用于预约信道
                  • CTS：允许发送帧（Clear To Send），接收方对 RTS 的应答
              • 管理帧
                • 探测请求/探测响应
                  • 探测请求（Probe Request）：站点主动扫描时发送，用于寻找可用网络
                  • 探测响应（Probe Response）：AP 收到探测请求后回复，告知网络信息
            • 数据帧格式
              • 30N4首数验，首部3+1地址
              • 90比特表去来 帧的中转靠AP
              • 去往AP中起止 来自AP止中起
            • 802.11的其他要点
              • 使用CSMA/CA协议实现介质访问控制
              • 移动站之间不能通信，通过AP转发帧
              • AP实现帧格式转换，可以将无线链路的802.11帧和有线链路的802.3帧相互转换
              • AP与移动站之间用无线链路；AP与AP、AP与路由器或交换机之间用有线链路
      • 设备
        • 以太网交换机
          • 以太网交换机的特点
            • 工作在数据链路层，根据接收方MAC转发帧
          • 自学习功能
            • 交换表
              • 初始为空，记录MAC和端口对应关系
            • 收到一个帧，就把发送方的MAC和端口更新到交换表
            • 没有接收方记录，就广播到其他所有端口
            • 有接收方记录，就转发到记录的端口
            • 记录过期作废
          • 交换方式
            • 直通交换
              • 只检查帧目的MAC地址，决定转发端口后立即转发
              • 转发延迟低
              • 不支持速率匹配，协议转换，差错控制
            • 存储转发交换
              • 先把帧完整存到高速缓存，进行处理后再转发
              • 支持速率匹配，协议转换，差错控制
              • 转发延迟高
      • 广域网
        • PPP协议
          • PPP的特点
            • 只支持全双工链路
          • PPP应满足的要求
            • 简单
              • PPP对帧格式和交互过程尽量简单，不设复杂功能
            • 封装成帧
              • 把网络层交下来的 IP 数据报封装成 PPP 帧，实现帧定界
            • 透明传输
              • 对数据中出现的与控制字符相同的字节进行转义，使数据能透明传输
            • 多种网络层协议
              • PPP 可在同一条物理链路上同时承载多种网络层协议的数据报
            • 多种类型链路
              • PPP 能在多种类型的链路上运行，如串行的同步、异步链路以及电、光链路
            • 差错检测
              • PPP 对收到的帧进行差错检测，能检测出帧的比特差错（只检错不纠错）
            • 检测连接状态
              • PPP 能及时自动检测出链路是否处于正常工作状态
            • 最大传送单元
              • PPP 对每种类型的链路设置最大传送单元 MTU 的默认值
            • 网络层地址协商
              • PPP 提供机制使通信的两个网络层实体能协商知道或配置彼此的网络层地址
            • 数据压缩协商
              • PPP 提供方法来协商使用数据压缩算法
          • PPP不需满足的要求
            • 纠错
              • PPP只进行检错，不进行纠错
            • 流量控制
              • PPP不进行流量控制
            • 序号
              • PPP不使用帧序号，因此不保证按序交付
            • 不支持多点线路
              • PPP只支持点对点链路，一条链路只连接两个结点
          • 组成部分
            • 把IP数据报封装到串行链路的方法
            • 链路控制协议LCP
              • LCP负责数据链路的建立、配置、测试和关闭
              • LCP用于协商链路层参数，如最大接收单元和认证方式
            • 网络控制协议NCP
              • NCP是一组协议，负责为各网络层协议分配和配置网络地址
              • PPP可在一条链路上同时运行多种网络层协议，各用对应的NCP
          • 状态图
            • 无链路→物理链路→LCP链路→已鉴别的LCP链路→已鉴别的LCP链路和NCP链路
          • 帧格式
            • 1112n21 界固固协数验界
            • 界01111110转义01111101
    • 网络层
      • 网络层的主要功能
        • 异构网络互联
          • 路由器也被称为网关
          • 不同网络的链路层协议和数据格式不同，网络层通过 IP 协议互联，向上提供统一的 IP 数据报服务
        • 路由和转发
          • 路由
            • 各个路由器相互配合，规划IP数据包路径
            • 路由表
              • 记录到达各目的网络（前缀）的路径信息，由路由选择协议生成
          • 转发
            • 一台路由器，根据转发表转发IP数据包
            • 转发表
              • 由路由表导出，保存分组转发时实际使用的接口映射
        • 虚电路和数据报
          • 虚电路
            • ①通信前先建立网络层连接（虚电路），这是逻辑连接，其传输路径在建立时确定
            • ②通信过程分3个阶段：虚电路建立、数据传输和虚电路释放
            • ③每个虚电路用虚电路号 VCID 区分，仅连接建立时使用完整目的地址，之后只需携带 VCID。路径上每个结点都维护一张虚电路表，记录 VCID 和下一跳结点（入/出端口）
            • ④建立拆除需要额外开销；分组不含目的地址，减小了开销，适合长时间频繁交换；连接建立后传输路径确定；能保证分组正确有序到达；某结点失效会破坏经过它的所有虚电路
          • 数据报
            • ①不需要建立连接
            • ②尽力交付，不保证可靠性
            • ③发送分组包含完整发送方和接收方地址，可以单独传输
            • ④交换结点存储转发时需要等候处理，带来时延
            • ⑤路径冗余，某个结点失效可以另寻路径转发
            • ⑥不独占链路
          • 数据报服务与虚电路服务比较
            • 连接的建立：数据报服务不需要；虚电路服务必须有
            • 目的地址：数据报服务每个分组都有完整的目的地址；虚电路服务仅在建立连接阶段使用，之后每个分组使用长度较短的虚电路号
            • 路由选择：数据报服务每个分组独立地进行路由选择和转发；虚电路服务属于同一条虚电路的分组按照同一路由转发
            • 分组顺序：数据报服务不保证分组的有序到达；虚电路服务保证分组的有序到达
            • 可靠性：数据报服务不保证可靠通信，可靠性由用户主机来保证；虚电路服务可靠性由网络保证
            • 对网络故障的适应性：数据报服务出故障的节点丢失分组，其他分组路径选择发生变化时可以正常传输；虚电路服务所有经过故障节点的虚电路均不能正常工作
            • 差错处理和流量控制：数据报服务由用户主机进行流量控制，不保证数据报的可靠性；虚电路服务可由分组交换网负责，也可由用户主机负责
        • 软件定义网络（SDN）
          • ①控制平面上远程控制器集中路由，数据平面转发设备分布转发
          • ②编程接口
            • 北向接口：SDN提供的编程接口
            • 南向接口：控制器和转发设备双向会话接口
            • 东西向接口：控制器之间的接口
          • ③特点
            • Ⅰ全局集中控制和分布高速转发，利于控制平面优化和高性能网络转发
            • Ⅱ灵活可编程和性能的平衡
            • Ⅲ降低成本，网络设备制造和功能软件开发分离
          • ④安全风险，集中管理容易受攻击；网络规模扩大，控制器可能成为网络性能瓶颈
        • 拥塞控制
          • 拥塞
            • 网络上出现过量分组，超负荷，网络性能下降
          • 拥塞控制方法
            • 开环控制（静态）
              • 在部署网络时就提前设计好预防拥塞的方法
            • 闭环控制（动态）
              • 动态监视网络状态，及时发现拥塞，让路由器及时调整路由表
      • IPv4
        • IPv4分组
          • 结构
            • 首部
              • 固定部分（20字节）
                • 版本占 4 位
                • 首部长度占 4 位
                • 区分服务占 8 位
                • 总长度占 16 位
                • 标识占 16 位
                • 标志占 3 位
                • 片偏移占 13 位
                • 生存时间占 8 位
                • 协议占 8 位
                • 首部检验和占 16 位
                • 源地址占 32 位
                • 目的地址占 32 位
              • 可变部分（0～40字节）
                • 可选字段（长度可变）
                • 填充
              • 首部由固定部分（20字节）与可变部分（0～40字节）组成，首部之后为数据部分
              • 发送在前：首部在前，数据部分在后，二者合称 IP 数据报
            • 数据
              • 承载上层协议的数据（如 TCP 报文段、UDP 数据报）
          • 分片问题
            • MTU（最大传送单元）
              • 数据链路层帧可承载的最大数据量
            • IP数据包总长度大于下一链路MTU，就要分片
            • 除最后一个外，其他分片数据部分是8B整数倍
            • 标识16bit区分分片属于哪个IP数据报
            • 标志3bit，最低位MF，次低位DF
            • 片偏移以 8 字节为单位，表示该分片在原数据报中的相对位置
          • TTL字段
            • 经过一个路由器，TTL减1，到0时路由器丢弃分组，并向原主机发送ICMP报文
            • 用于防止 IP 数据报在网络中无限制地循环转发
        • IPv4地址
          • 分类编址
            • A、B、C 类为单播地址
            • D 类为多播地址
            • E 类保留
            • 网络号+主机号
              • IP 地址由网络号与主机号两部分组成，网络号标识所在网络，主机号标识网络内的主机
            • 每台主机和路由器接口分配全球唯一IP地址
            • 同一网络网络号相同
            • 新主机接入后分配IP地址和配置默认网关
            • 主机发送时先判断目的地址和本机地址的网络号，同网络号直接发送到指定主机，非同网络号发送到默认网关（需要根据ARP协议由IP转MAC）
            • 路由器根据转发表转发IP分组到指定端口（按类取IP地址的网络号，然后和转发表记录依次对比）
            • 特殊用途IP地址
              • 网络号 Y、主机号全0：作源地址否，作目的地址否；含义为表示整个网络本身（只能用于路由表、转发表）
              • 网络号 Y、主机号全1：作源地址否，作目的地址是；含义为向网络号为 Y 的网络广播 IP 分组
              • 网络号 0、主机号 Y：作源地址是，作目的地址否；含义为表示本网络中主机号为 Y 的主机
              • 网络号全0、主机号全0：作源地址是，作目的地址否；含义为本网络上的本主机（会在 DHCP 协议中使用）
              • 网络号全1、主机号全1：作源地址否，作目的地址是；含义为向本网络广播 IP 分组
              • 网络号 127、主机号为非全0或非全1的任何数：作源地址是，作目的地址是；含义为环回自检地址，表示一台主机本身，用于本地软件环回测试
              • 主机号占 $N$ 位时，最多有 $2^N-2$ 个主机
          • 子网划分
            • 划分子网的方法
              • 将 $n$ 位主机号的前 $k$ 位作为子网号，可划分 $2^k$ 个子网
              • 每个子网中，主机不能分配全0或全1
            • 子网掩码
              • 作用
                • 与IP地址逐位与，算出网络前缀
                • 网络前缀相同的才属于同一网络
              • 注意
                • 如果网络进行了子网划分，那么网络中所有主机，路由器接口都要配置IP地址，默认网关，子网掩码
                • 支持子网划分技术的路由器转发项包括 目的网络号+子网掩码+转发端口
            • 默认子网掩码
              • 传统网络内部没有进行子网划分，转发表项设置为默认子网掩码，A8B16C24
            • 默认路由
              • 默认转发表项设置 目的网络号全0，子网掩码全0
              • 其他表项不能匹配，默认路由一定匹配
            • 主机发送IP数据报过程
              • 判断目的主机和本机是否属于同一网络
                • 检查本机IP地址和目的IP地址网络前缀是否相同
                • 网络前缀通过与子网掩码逐位与获得
                • 相同就属于同一网络，不同就不属于
              • 将IP数据报封装成MAC帧并发送到链路上
                • 如果属于同一网络，就通过ARP获得目的主机MAC地址，封装帧发送给目的主机
                • 如果不属于同一网络，就通过ARP获得默认网关MAC地址，封装帧发送给默认网关
            • 路由器转发IP数据包过程
              • 从某一个接口收到一个IP数据包
              • 对IP数据报首部进行校验，并找到目的IP地址
              • 查转发表
                • 转发表项包含 目的网络号+子网掩码+转发接口
                • 目的IP与子网掩码按位与，与目的网络号匹配
                • 默认路由保证一定可以匹配成功
              • 转发
                • 根据查找结果，将IP数据报从匹配转发端口转发
                • 若匹配端口与IP数据报入口相同，就不再转发
        • CIDR
          • 原理
            • 取消传统分类，使IP地址块更灵活，利用率更高
            • IP 地址 $=$ 网络前缀 $+$ 主机号，网络前缀长度可变
            • CIDR 记法：$a.b.c.d/x$
          • 子网划分
            • 定长子网划分
              • 将主机号前 $k$ 位作为定长子网号，可划分 $2^k$ 个子网
            • 变长子网划分
              • 划分子网时，子网号长度大小不同
              • 变长子网划分技巧
                • 从根到叶构造二叉哈夫曼树
                • 原始地址块作为根结点
                • 每个分支结点必须同时有左右孩子，分别对应01
                • 每个叶子结点对应一个子网，根据路径确定子网IP地址
                • 整棵树高度不能超过 $h-1$，最小子网需要 $2$ 位主机号
            • 每个子网中主机号全 0 或全 1 的地址不能分配
        • 路由聚合
          • 转发接口相同、部分网络前缀也相同的路由表项可以聚合为一条
          • 最长前缀匹配原则
            • 采用路由聚合，IP地址可能匹配多个表项

        • ICMP
          • ICMP 是网络层协议，但被封装在 IP 数据报中发送
          • 分类
            • 差错报告报文
              • 终点不可达、源点抑制、时间超过、参数问题、改变路由
                • 终点不可达：路由器或主机无法将数据报交付给目的端时，向源点发送
                • 源点抑制：路由器或主机因拥塞而丢弃数据报时，向源点发送，使其放慢发送速率（已废弃）
                • 时间超过：路由器将生存时间减为 $0$ 的数据报丢弃时，或目的主机未在规定时间内收齐全部分片时发送
                • 参数问题：数据报首部字段取值有误时发送；改变路由（重定向）：路由器通知源点改走更好的路由
              • 不发送差错报告报文的情况
                • 对携带差错报告报文的数据报不再发送差错报告
                • 对第一个分片之后的各分片不发送差错报告
                • 对多播地址的数据报不发送差错报告
                • 对特殊地址（如 $127.0.0.1$）不发送差错报告
            • 询问报文
              • 回送请求和回答报文
                • 由主机或路由器向目的主机发送回送请求报文，收到该报文的主机返回回送回答报文
                • 用于测试目的主机或路由器是否可达、是否工作正常，ping 命令即使用该报文
              • 时间戳请求和回答报文
                • 由主机发送时间戳请求报文，目的主机返回时间戳回答报文
                • 时间戳字段是从子夜开始计算的毫秒数，可用于测量往返时间

      • 路由算法和路由协议
        • 路由算法
          • 距离向量路由算法
            • Bellman-Ford算法
              • $d_x(y)=\min_v\{c(x,v)+d_v(y)\}$，其中 $v$ 是 $x$ 的所有邻居
            • 每个结点都保存下列路由信息
              • ① $x$ 到所有直接邻居 $v$ 的链路费用 $c(x,v)$
              • ② $x$ 的距离向量，即 $x$ 到所有其他结点的费用
              • ③ $x$ 的所有直接邻居 $v$ 的距离向量
              • 结点 $x$ 定期向每个邻居发送它的距离向量；邻居收到后先用 Bellman-Ford 算法更新自己的距离向量，若发生改变则继续向邻居发送更新
          • 链路状态路由算法
            • 每个结点都有全局拓扑结构图，可用 Dijkstra 算法计算到达其他结点的最短路径
            • ①结点主动测试所有相邻结点的状态
            • ②定期将链路状态广播给所有其他结点
        • 路由协议
          • RIP路由信息协议
            • 规定
              • ①网络中每个路由器维护它到目的网络的距离向量
              • ②使用跳数来衡量到达目的网络的距离，规定从路由器到直接连接网络的距离定义为1，每经过一个路由器，距离加1
              • ③一条路径最多包含 15 个路由器，16 表示不可达，只适用于小型互联网
              • ④每个路由表项包括：<目的网络 N，距离 d，下一跳路由器地址 X>
              • ⑤固定间隔交换路由信息，网络拓扑发生变化时即时通报相邻路由器
              • ⑥采用距离向量算法，选择跳数最少（距离最短）的路径
            • 步骤
              • 收到相邻路由器X发来的RIP报文，先修改报文项目，把下一跳都改为X，距离+1，对每个报文项目执行以下步骤：
                • ①如果原来路由表没有目的网络N，且距离小于16，则该项加入路由表
                • ②如果原来的路由表有目的网络N，且下一跳是X，则替换原来项
                • ③如果原来的路由表有目的网络N，且下一跳不是X，如果收到的项目距离小于原来路由表距离，则替换原来项
                • 路由表项有180秒老化计时器，如果180秒没有更新，则距离设置为16，并开启120秒垃圾回收计时器，向邻居通报4次后删除
            • 优缺点
              • 优点：实现简单、好消息传播快
              • 缺点：网络规模受限（不超过 15 跳）、每次交换完整路由表开销大、坏消息传播慢
          • OSPF开放最短路径优先协议
            • 特点
              • ①使用洪泛法向本AS所有路由器发送信息
              • ②发送信息是与本路由器相邻的所有路由器链路状态
              • ③只有链路发生变化时，才用洪泛法发送，更新过程收敛快
            • 原理
              • 路由器之间交换链路状态信息，所有路由器都有完整的链路状态数据库，再用 Dijkstra 算法计算到达目的网络的最优路径并构造路由表
            • 分组类型
              • ①问候分组：发现和维持邻站的可达性
              • ②数据库描述分组：向邻站给出自己的链路状态数据库
              • ③链路状态请求分组：向对方请求发送某些链路状态项目
              • ④链路状态更新分组：洪泛法对全网更新链路状态
              • ⑤链路状态确认分组：对更新分组的确认
          • BGP边界网关协议
            • 特点
              • 两个相邻的AS通过各自边界路由器半永久TCP直接相联，AS内部路由器之间也通过半永久TCP相联。每对TCP连接的路由器称为BGP对等方，发送BGP报文的TCP连接称为BGP会话。跨越AS的BGP会话称为外部BGP（eBGP），同一个AS中的BGP会话称为内部BGP（iBGP）
            • BGP路由
              • BGP 路由 $=\langle$CIDR前缀，BGP属性$\rangle$
                • BGP属性包括AS-PATH和NEXT-HOP
                • AS-PATH表示经过的所有AS
                • NEXT-HOP表示到达该前缀的下一跳路由器地址
            • 路由选择
              • ①选择本地偏好值最高的路由
              • ②选择AS跳数（AS-PATH）最少的路由
              • ③使用热土豆路由选择算法
              • ④选择BGP标志符最小的路由
            • 四种报文
              • Open（打开）报文：建立关系，通信初始化
              • Update（更新）报文：通知某一路由信息，列出要撤销的多条路由
              • Keepalive（保活）报文：周期性证实邻站连通性
              • Notification（通知）报文：用来发送检测到的差错
        • 对比
          • 协议分层
            • 内部网关协议：RIP、OSPF
            • 外部网关协议：BGP
          • 各协议报文所采用的传输协议
            • RIP 是应用层协议，使用 UDP 传送数据
            • OSPF 是网络层协议，使用 IP 传送数据
            • BGP 是应用层协议，使用 TCP 传送数据
          • 三种路由协议比较
            • 类型：RIP：内部；OSPF：内部；BGP：外部
            • 路由算法：RIP：距离向量；OSPF：链路状态；BGP：路径向量
            • 传递协议：RIP：UDP；OSPF：IP；BGP：TCP
            • 路径选择：RIP：跳数最少；OSPF：代价最低；BGP：较好，非最佳
            • 交换节点：RIP：和本节点相邻的路由器；OSPF：网络中的所有路由器；BGP：和本节点相邻的路由器
            • 交换内容：RIP：当前本路由器知道的全部信息，即自己的路由表
            • 交换内容：OSPF：与本路由器相邻的所有路由器的链路状态
            • 交换内容：BGP：首次为整个路由表，非首次为有变化的部分
      • IP多播
        • IP分组传输方式
          • 单播，广播，组播
            • 单播：一个源点发送到一个目的点
            • 广播：一个源点发送到同一网络中的所有结点
            • 组播（多播）：一个源点发送到属于同一组播组的一组结点
        • 组播地址
          • 属于多播组的设备分配一个组播组IP地址
          • D类地址是组播地址，只能作为目的地址
        • 特点
          • 尽力交付
          • 不产生ICMP差错报文
          • D类地址都是组播地址，但其中部分（如224.0.0.0/24）为路由协议等保留，不能随意使用
        • 硬件组播
          • 组播 IP 地址映射为组播 MAC 地址
            • 组播 MAC 地址的构造
              • 第 25 位固定为 $0$
              • 后 23 位取 IP 组播地址的后 23 位
              • 前 24 位固定为 $01$-$00$-$5E$
            • IP 组播地址有效位 $28$ 位，MAC 组播地址有效位 $23$ 位，因此可能收到不属于自己的组播帧
              • IP 层也要过滤掉不属于自己的组播分组
        • 因特网范围组播
          • IGMP协议
            • 让本地组播路由器知道本局域网是否有主机加入或退出某个组播组
            • 工作方式
              • 主机加入组播组时，主机向组播组的组播地址发送IGMP报文，声明加入。本地组播路由器收到IGMP报文后通过组播路由选择协议通知互联网其他组播路由器
              • 本地组播路由器周期询问局域网主机是否仍为某组播组成员；有一个响应就认为活跃，几次询问无响应则认为本网络没有该组播组的主机
          • 组播路由选择协议
            • 构造以源主机为根结点的组播转发树，避免兜圈子
            • 不同组播组转发树不同，同一转发组不同源结点的转发树也不同
            • 算法
              • 基于链路状态的路由选择
                • 各路由器了解全网拓扑，用链路状态算法计算以源结点为根的最短路径树，据此构造组播转发树
              • 基于距离-向量的路由选择
                • 各路由器与相邻路由器交换距离向量信息，用距离向量算法构造组播转发树
              • 协议无关的组播（稀疏/密集）
                • 协议无关组播（PIM）不依赖具体的单播路由协议
                • 密集模式（PIM-DM）采用洪泛加剪枝，适合组成员密集分布
                • 稀疏模式（PIM-SM）用汇聚点构造共享树，适合组成员稀疏分布
      • 移动IP
        • 目标：设备移动但 IP 地址不变
        • 概念
          • 移动结点、归属代理（本地代理）、永久地址（归属地址/主地址）、外部代理（外地代理）、转交地址（辅地址）
            • 移动结点：拥有永久地址、可移动到外地网络接入的主机
            • 归属代理（本地代理）：归属网络上的路由器，把发往移动结点的分组经隧道转发到其转交地址
            • 永久地址（归属地址/主地址）：移动结点的固定地址，移动过程中保持不变
            • 外部代理（外地代理）与转交地址（辅地址）：外部代理是外地网络上的路由器，为移动结点分配转交地址；转交地址是移动结点在外地网络获得的临时地址，指明其当前所在位置
          • 移动结点离开归属网络后由外部代理分配转交地址，归属代理把发往永久地址的分组经隧道转发到转交地址
      • 设备
        • 冲突域与广播域
          • 冲突域：同一网段上可能发生冲突的结点集合
          • 集线器（Hub）所有端口属于同一个冲突域，交换机每个端口是独立的冲突域
          • 广播域：能收到同一广播帧的结点集合
          • 交换机所有端口默认属于同一个广播域；路由器每个接口既是独立的冲突域也是独立的广播域
    • 传输层
      • 概述
        • 功能
          • 实现进程到进程通信
            • 网络层负责主机到主机的通信，传输层负责应用进程到应用进程的通信
            • 用端口号区分同一主机上的不同应用进程
          • 复用和分用
            • 复用
              • 发送数据时，多个应用进程共用一个传输层协议
            • 分用
              • 接收数据后，传输层把数据交付给目的应用进程
          • 差错检测
            • TCP出错后丢弃数据，并通知重发
            • UDP出错后丢弃数据，不通知发送方
          • 向应用层提供两种服务
            • 有连接的、可靠的传输服务TCP
              • 准确，慢
            • 无连接的、不可靠的传输服务UDP
              • 不准确，快
        • 端口的作用
          • 标识本主机的一个特定进程
            • 不同主机端口独立
            • TCP、UDP端口独立
          • TCP或UDP通过套接字标识某台主机的某个进程
          • 端口号0～1023只能用于熟知程序
        • UDP和TCP对比
          • UDP
            • 首部小，8B
            • 每次一个完整报文，不支持拆分重装
            • 无连接的，不可靠的，不支持拥塞控制
            • 支持一对一、一对多、多对一、多对多（广播、多播分组）
          • TCP
            • 首部更大，20-60B
            • 可以传输长报文，支持自动拆分重装
            • 有连接的，可靠的，支持拥塞控制
            • 仅支持一对一（因为需要先建立连接）
      • UDP
        • 数据报
          • UDP数据报格式
            • 首部共8B，四个字段各占16位
            • 16位源端口号
              • 位于 UDP 首部第 1～2 字节，标识发送方进程的端口号
              • 当不需要对方回复时，可置为全 0
            • 16位目的端口号
              • 位于 UDP 首部第 3～4 字节，标识接收方进程的端口号
              • 必须填写，不能省略
            • 16位UDP长度
              • 位于 UDP 首部第 5～6 字节，给出 UDP 数据报的总长度
              • 包含 8 B 首部和数据部分，单位为字节
              • 最小值为 8，即只有首部而没有数据时
            • 16位UDP校验和
              • 位于 UDP 首部第 7～8 字节，检验首部和数据部分在传输中是否出错
              • 若发送方不计算校验和，可将该字段置为全 0
            • 数据（如果有）
              • UDP 首部之后的数据部分，存放应用层交下来的报文
              • 长度可变，可以为 0 字节
          • 源端口号
            • 不需要回复可以设置为全0
          • 目的端口号
            • 必填
          • 数据报长度
            • 包含首部，单位B
          • 校验和
            • 如果无需校验，可以全0
        • 校验和计算
          • 校验算法
            • 计算：原始数据16bit一组，二进制累加（最高位进位加回最低位），运算结果取反得16bit校验和
            • 校验：收到的内容16bit一组，二进制累加（最高位进位加回最低位），全1没有差错，否则有差错
          • UDP校验
            • 发送方计算校验和前需要添加伪首部，计算完成后拆除
            • 接收方校验前需要添加伪首部，校验完成后拆除
              • 校验出差错，直接丢弃
          • IP校验
            • 不会增加伪首部，只校验首部
      • TCP
        • 概述
          • 三个阶段：建立连接，数据传输，释放连接
          • 每次建立TCP连接，可以传输多个报文
          • TCP面向字节流，UDP面向报文
        • TCP段
          • TCP段格式
            • 固定首部20B，每行为32位
            • 第一行：源端口（16位）、目的端口（16位）
            • 第二行：序号（32位）
            • 第三行：确认号（32位）
            • 第四行：数据偏移、保留、URG、ACK、PSH、RST、SYN、FIN、窗口
            • 第五行：校验和（16位）、紧急指针（16位）
            • 第六行：选项（长度可变）、填充
          • 源端口、目的端口
            • 各占 16 位，用于区分同一主机上的不同进程
            • 源端口标识发送方进程，目的端口标识接收方进程
          • 序号（seq）
            • 标记数据部分第一个字节在原始流中的序号
            • 起始序号发送方设置，不一定为0
          • 确认号（ack/ack_seq）
            • 反馈，表示在此号之前的字节都已正确收到，希望之后收到此号开始的数据
            • 标记ACK=1时，确认号ack才有效
            • 只有握手1的ACK=0
          • 数据偏移
            • 就是TCP首部长度，以4字节为单位
            • 数据部分长度=IP数据部分长度-TCP首部长度
          • 标记位
            • URG紧急位
              • =1时表示是紧急数据
            • PSH推送位
              • =1时表示发送方希望接收方尽快将数据交付应用进程（不必等缓存填满，用于交互式通信）
            • RST复位位
              • =1时表示出现严重错误，必须释放连接。或拒绝一个非法报文段
            • SYN同步位
              • =1时表示是连接请求或连接接受报文，只有握手1或握手2时SYN=1，SYN段
            • FIN终止位
              • =1时表示此报文段发送方数据已发送完毕，要求断开连接，只有挥手1和挥手3时FIN=1，FIN段
            • ACK位
              • =1时表示确认号字段有效
          • 窗口（rwnd）
            • 接收窗口大小，从本报文 ack_seq 开始，接收方还能接收多少数据，单位 B
            • 流量控制关键
          • 校验和
            • 同UDP，也有伪首部
          • 紧急指针
            • 紧急数据的指针，标记URG=1时有效
          • 选项
            • 握手时协商MSS
              • 最大段长MSS表示接下来数据传输，一个TCP段最多携带多少数据（不含头部）
        • 连接管理
          • 建立连接
            • 步骤
              • 握手1
                • SYN=1，ACK=0，FIN=0，seq=666，ack无效
              • 握手2
                • SYN=1，ACK=1，FIN=0，seq=50，ack=667
              • 握手3
                • SYN=0，ACK=1，FIN=0，seq=667，ack=51
            • 要点
              • 只有握手1、2的SYN=1
              • TCP全过程中，只有握手1的ACK=0
              • 握手1、2不能携带数据，握手3可以携带数据
              • 握手1、2固定消耗1个序号
              • 握手3如果不携带数据就不消耗序号
            • 状态
              • 客户进程
                • CLOSED => （发送握手1）SYN-SENT => （收到握手2，发送握手3）ESTABLISHED
              • 服务器进程
                • CLOSED => LISTEN => （收到握手1，发送握手2）SYN-RCVD => （收到握手3）ESTABLISHED
            • 耗时分析
              • 发送握手1，到客户端发送数据，至少需要1RTT
              • 发送握手1，到服务器发送数据，至少需要1.5RTT
          • 释放连接
            • 步骤
              • 挥手1
                • SYN=0，ACK=1，FIN=1，seq=9999，ack=5600
              • 挥手2
                • SYN=0，ACK=1，FIN=0，seq=5600，ack=10000
              • 挥手3
                • SYN=0，ACK=1，FIN=1，seq=7800，ack=10000
              • 挥手4
                • SYN=0，ACK=1，FIN=0，seq=10000，ack=7801
            • 要点
              • 只有挥手1，挥手3的FIN=1
              • 挥手1、3即使不携带数据，也要消耗一个序号
              • 挥手2可以携带数据
              • 挥手4不可以携带数据
            • 状态
              • 先手
                • ESTABLISHED => （发送挥手1）FIN-WAIT1 => （收到挥手2）FIN-WAIT2 => （收到挥手3，发送挥手4）TIME-WAIT => （倒计时时间到）CLOSED
              • 后手
                • ESTABLISHED => （收到挥手1，发送挥手2）CLOSE-WAIT => （发送挥手3）LAST-ACK => （收到挥手4）CLOSED
            • 补充
              • 收到挥手3启动2MSL倒计时，重复收到挥手3重置计时
              • 最长报文段寿命MSL，固定时间长度
            • 耗时分析
              • 发送挥手1，到先手CLOSED，至少需要1RTT+2MSL
              • 发送挥手1，到后手CLOSED，至少需要1.5RTT
        • 可靠传输和流量控制
          • 可靠传输
            • 序号
              • 建立连接时确定起始序号，一个字节对应一个序号
            • 确认机制
              • 累积确认
                • ack_seq=n表明n之前的字节都已经收到
              • 返回ACK时机
                • 推迟确认
                  • 推迟时间不超过0.5秒
                  • 如果自己也有数据发送，直接捎带确认
                  • 连续两个长度MSS段立即确认
              • 两种ACK
                • 专门确认
                  • 不携带数据
                • 捎带确认
                  • 携带数据
            • 重传机制
              • 超时重传
                • 每发出一个段，就设置一个计时器，计时器到期未确认就重传段，并重置计时器
                • 超时重传时间 $RTO$ 略大于加权平均往返时间 $RTT_S$，$RTT_S$ 随 RTT 样本值变化
                • 重传的报文段不作为 RTT 样本（Karn 算法），避免确认二义性导致 $RTO$ 估计偏差
              • 快重传
                • 让出错段尽早重传，而不是超时重传
                • 立即确认
                  • 收到段，就立即返回ACK段
                  • 收到失序段也立即返回ACK段（产生冗余ACK）
                • 连续收到三个确认号相同的冗余ACK，就立即重发对应段
          • 流量控制
            • 接收方维持一个接收窗口
              • 接收窗口不大于已确认序号后可用接收缓冲区大小
              • 接收窗口是接收方还允许接收的序号范围
            • 发送方维持一个发送窗口
              • 发送窗口不大于发送缓冲区大小
              • 发送窗口不大于接收窗口大小
              • 发送窗口是发送缓冲区中已经发送但尚未确认的数据和可以发送但未发送的数据
        • 拥塞控制
          • 算法
            • 慢开始算法
              • （$cwnd<ssthresh$ 时）$cwnd$ 从 1 开始，每收到一个 ACK，$cwnd$ 加 1
            • 拥塞避免算法
              • （$cwnd\ge ssthresh$ 时）每经过一个 RTT，$cwnd$ 加 1（加法增大）
          • 网络拥塞
            • 发生超时重传，严重拥塞
              • 阈值 $ssthresh$ 减为 $cwnd$ 的一半
              • $cwnd$ 从 1 开始
          • TCP拥塞窗口变化
            • 纵轴为拥塞窗口 $cwnd$，横轴为传输轮次
            • 慢开始阶段：$cwnd$ 从 1 开始按指数规律增长
            • 当 $cwnd$ 增长到慢开始门限 $ssthresh$（示例初始值 16）时，转为拥塞避免
            • 拥塞避免阶段：$cwnd$ 按“加法增大”线性增长
            • 当 $cwnd$ 达到 24 时发生网络拥塞
            • 拥塞后按“乘法减小”将 $ssthresh$ 设为 12（当前 $cwnd$ 的一半），并将 $cwnd$ 降为 1
            • 随后重新进入慢开始，$cwnd$ 按指数规律增长到新的 $ssthresh$ 值 12
            • 到达 $ssthresh$ 后再次进入拥塞避免，按“加法增大”线性增长
          • 要点
            • 发送窗口上限 $=\min(rwnd,cwnd)$
            • 默认每个TCP段都以MSS满载数据
            • 拥塞窗口大小以MSS的倍数为单位
            • 立即确认
              • 接收方每收到一个报文段就立即返回 ACK，不采用推迟确认
              • 是快重传能尽快发现丢包、发送方尽早重传的前提
            • 慢开始阶段，若 $2\,cwnd>ssthresh$，则下一个 RTT 后的 $cwnd$ 等于 $ssthresh$
          • 快重传和快恢复
            • 快重传
              • ①接收方立即确认
              • ②收到失序报文段立即重复确认
              • ③连续收到3个重复确认就立即重传
            • 快恢复
              • ①收到 3 个重复确认后，把 $ssthresh$ 减为 $cwnd$ 的一半，$cwnd$ 也减为一半，之后执行拥塞避免算法；跳过了从 1 开始，所以称为快恢复
              • ②超时重传采用慢开始，收到 3 个重复确认采用快重传和快恢复
    • 应用层
      • 网络应用模型
        • C/S模型
          • ①服务器等待接收请求，客户机发出请求并等待结果，服务器收到分析和处理请求并把结果返回客户
          • ②客户是服务请求方，服务器是服务提供方
          • ③常见应用 Web、FTP、远程登录、电子邮件
          • ④特点：各计算机地位不相等，客户机相互之间不直接通信，可扩展性不佳
        • P2P模型
          • ①所有计算机没有固定客户和服务器划分，每个计算机都是对等方，直接相互通信
          • ②优点：减轻了服务器压力，直接共享，可扩展性好，网络健壮性强
          • ③缺点：获取服务同时还要提供服务，占用较多内存
      • 域名系统
        • 层次域名空间
          • ①域名由标号序列组成，从左到右级别依次升高（如三级域名、二级域名、顶级域名）
          • ②顶级域名包括：国家（地区）顶级、通用顶级、基础结构域名
        • 域名服务器
          • 域名服务器的类型
            • 根域名服务器：最高层次的域名服务器，知道所有顶级域名服务器的域名和 IP 地址
            • 顶级域名服务器：负责管理在该顶级域名服务器注册的所有二级域名
            • 权限域名服务器：负责一个区的域名解析，记录管辖范围内域名与 IP 地址的对应关系
            • 本地域名服务器：主机发出 DNS 查询请求时首先求助于它
          • 域名服务器层次结构
            • 根域名服务器：最高层，所有根域名服务器都知道所有顶级域名服务器地址
            • 顶级域名服务器：如com域名服务器、org域名服务器、cn域名服务器
            • 权限域名服务器：负责具体区域的域名解析
            • 示例：cskaoyan.com域名服务器、edu.cn域名服务器、hust.edu.cn域名服务器
            • 层级关系：根域名服务器→顶级域名服务器→权限域名服务器
        • 域名解析
          • 递归查询和迭代查询
            • ①主机向本地域名服务器查询一般采用递归查询
            • 两种查询方式的含义
              • 递归查询：主机向本地域名服务器查询时，由本地域名服务器代替主机向其他域名服务器继续查询，最终把结果返回主机
              • 迭代查询：本地域名服务器向根或上级域名服务器查询时，被查询服务器要么返回 IP 地址，要么告诉本地域名服务器下一步该向哪个域名服务器查询
            • (a) 本地域名服务器采用递归查询：主机 → 本地域名服务器（递归①）；本地域名服务器 → 根 → 顶级 → 权限 逐级递归②③④⑤，再逐级返回⑥⑦⑧，最后由本地域名服务器把 y.abc.com 的 IP 地址返回主机
            • (b) 本地域名服务器采用迭代查询：本地域名服务器依次向 根② → 顶级⑤ → 权限⑥⑦ 迭代查询，各级只返回「下一步该问谁」的地址④，最终由权限域名服务器返回 IP，本地再返回主机⑧
            • 主机对本地域名服务器一般为递归查询；本地域名服务器对上级服务器可用递归（a）或迭代（b）
            • ②本地域名服务器向根/上级域名服务器的查询通常采用迭代查询（也可采用递归）
          • 高速缓存
            • 主机和本地域名服务器都维护高速缓存
            • 缓存中保存近期查询过的域名及其IP地址映射
            • 再次查询相同域名时可直接由缓存回答，减少查询时延和网络流量
            • 每条映射都设置生存时间TTL，到期后从缓存中删除
            • 缓存可能过期，需向权威域名服务器更新以保证一致性
        • DNS服务使用53端口，查询通常用UDP，区域传送用TCP
      • 文件传输协议
        • FTP的进程与连接
          • 客户端：用户界面、控制进程、数据传送进程三个层次
          • 服务器端：控制进程、数据传送进程两个层次
          • 控制进程之间建立 TCP 控制连接，用于传送控制命令
          • 数据传送进程之间建立 TCP 数据连接，用于传送文件数据
          • 两条连接均经过因特网
          • 控制连接在整个会话期间保持打开，数据连接按需建立与关闭
        • 工作原理
          • ①FTP采用客户/服务器工作方式，使用TCP。一个FTP服务器进程同时为多个客户进程提供服务
          • ②主进程等待连接，收到连接后交给从属进程处理，主进程和从属进程并发执行
        • 控制连接和数据连接
          • 控制连接
            • ①服务器监听21号端口，等待客户连接，建立在这个端口上的连接称为控制连接
            • ②控制连接传送控制信息，不传送数据。数据传送时也可以通过控制连接发送控制信息
            • ③控制连接整个会话期间保持打开状态
          • 数据连接
            • ①服务端控制进程收到客户的文件传输请求后，会创建数据传送进程和数据连接
            • ②数据传送进程文件传送完毕后关闭数据传送连接并结束运行
            • ③数据连接有主动模式和被动模式，主动模式是服务端20端口连接到客户端随机开放的端口，被动模式是客户端连接到服务端随机开放的端口
            • ④FTP修改服务器的文件需要先完全传送到本地，修改后再传送回服务器
      • 电子邮件
        • 电子邮件发送与读取流程
          • 发送方用户代理：使用SMTP客户
          • 发送人用户代理通过 SMTP 将邮件发送到发送方邮件服务器
          • 发送方邮件服务器包含 SMTP 服务器（接收本域用户邮件）和 SMTP 客户（向对方服务器发送邮件）
          • 发送方邮件服务器与接收方邮件服务器之间通过 SMTP TCP 连接发送邮件
          • 接收方邮件服务器包含 SMTP 服务器和 POP3 服务器
          • 接收方用户代理：使用POP3客户
          • 收件人用户代理通过 POP3 TCP 连接从接收方邮件服务器读取邮件
        • ①邮件系统由用户代理、邮件服务器和协议组成
        • ②发送邮件使用SMTP协议，读取邮件使用POP3或IMAP协议，所有协议都使用TCP连接，都是客户服务器模式
        • ③邮件由信封和内容两大部分组成，内容再分为首部和主体，首部有严格格式、主体由用户自由撰写
        • ④SMTP协议只支持7位ASCII码数据，可以用MIME将非ASCII码数据转换为ASCII码数据后再通过SMTP发送
        • ⑤SMTP协议使用25端口，SMTP通信分三个阶段：连接建立、邮件传送、连接释放
        • ⑥POP3协议简单但功能有限，使用110端口，两种工作模式：下载并保留、下载并删除
        • ⑦IMAP复杂得多，允许客户只获取报文的部分信息，使用143端口
        • ⑧万维网流行后，用户代理和邮件服务器之间可以用HTTP协议收发邮件
      • 万维网
        • 组成
          • 万维网的三个组成部分
            • URL：统一资源定位符，唯一标识万维网上的各种文档
            • HTTP：超文本传送协议，是万维网客户与服务器之间交互所遵循的应用层协议
            • HTML：超文本标记语言，使万维网页面能在不同平台上显示
        • HTTP（默认端口 80，HTTPS 443）
          • 访问网页过程
            • 一个网页由 1 个 HTML 文件和 $n$ 个网页元素组成
            • 每个文件都需要通过一组HTTP请求和响应
            • 先获取 HTML 文件，才能知道其他被引用的网页元素
          • 工作方式
            • 非持续连接
              • 每建立一次TCP连接仅完成一组HTTP请求和响应
              • 可以并行TCP连接获取n个网页元素
            • 持续连接
              • 每建立一次连接，可以完成多组HTTP请求和响应
              • 分类
                • ①非流水线：每组HTTP请求和响应串行
                • ②流水线：可以连续发出多个HTTP请求
          • 报文结构
            • 报文的两种类型
              • HTTP 报文分为请求报文和响应报文两类
              • 请求报文由请求行、首部行、空行和实体主体组成
              • 响应报文由状态行、首部行、空行和实体主体组成
            • 请求报文：（a） 请求行 + 首部行 + 空行 CRLF + 实体主体（通常不用）
            • 请求行：方法、空格、URL、空格、版本、回车换行 CRLF
            • 响应报文：（b） 状态行 + 首部行 + 空行 CRLF + 实体主体（有些响应报文不用）
            • 状态行：版本、空格、状态码、空格、短语、回车换行 CRLF
            • 首部行：由若干「首部字段名、冒号、值、CRLF」组成
            • 空行：一个单独的 CRLF，用于分隔首部行与实体主体
          • 特点
            • 无连接的含义
              • 无连接指通信双方在交换 HTTP 报文之前不需要先建立 HTTP 连接
              • HTTP 仍使用 TCP 连接，由 TCP 保证可靠传输
            • 无状态的含义
              • 无状态指服务器不保存客户的任何状态信息，各次请求之间相互独立
              • 简化了服务器设计，但每次请求需重复提供信息，可用 Cookie 在客户与服务器之间传递状态
